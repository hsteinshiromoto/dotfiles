# 2026-11-26

## Atuin learned to capture Claude Code sessions

The ask was to connect atuin to Claude Code. Three links exist, and only the third is configured in this repository: the MCP server that gives Claude Code the `atuin_history`, `atuin_output` and `atuin_threads_*` tools, the `atuin hook claude-code` entries that put the commands Claude Code runs into atuin history, and thread capture, which records the sessions themselves. The first two are Claude Code configuration and live in `~/.config/nix/modules/features/home/claude.nix`. Thread capture is atuin configuration and lives here.

`.config/atuin/config.toml` gains two things. The commented `[daemon]` block now sets `enabled = true` and `autostart = true`; `autostart` was not in the 18.15.2 sample the file was built from, so it was added with a comment. At the end of the file a new `[threads]` section sets `capture = true`.

Capture runs in the daemon, not in the shell hook, so `[threads]` does nothing on its own. On macOS `autostart` registers a launchd agent at `~/Library/LaunchAgents/sh.atuin.daemon.plist`, and macOS announces a new background item the first time it appears.

### The key is `capture`, not `enabled`

Verified against the atuin source at tag `v18.24.8`, which is the version `pkgs.unstable.atuin` resolves to: the struct field is `capture`, with `capture_tools` and `resume_chooser` both defaulting to true, so neither was written. Upstream renames `threads.capture` to `threads.enabled` in 18.25.1. Whoever moves this repository past 18.24.x has to rename the key, and atuin will not complain when they forget: `Settings` does not derive `deny_unknown_fields`, so a stale key is read as nothing at all.

The `[daemon]` values were set inside the existing commented block rather than appended as a new section. A second `[daemon]` table is a TOML parse error.

### What this sends

Thread capture writes the contents of Claude Code sessions into the atuin record store and syncs them to the atuin server. The store is encrypted, but this is a genuine change in what leaves the machine, and it is wider than shell history: it is the conversation.

### Verification

The file parses, and `daemon` and `threads` read back as expected. Nothing was switched; the settings take effect on the host once it runs an atuin new enough to have the `threads` subcommand.

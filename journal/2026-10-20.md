# 2026-10-20

## opencode skill parity with Claude Code: three missing `name:` fields and one schema-correct `skills` array

### The request

Make opencode carry the same skills and MCP clients as Claude Code on this
machine. The first session survey had missed `~/.config/nix`, the declarative
source of truth for both tools, so the comparison was redone against the nix
modules before any change was planned.

### The MCP gap did not exist

`modules/features/home/mcp/render.nix` fans one MCP definition set out to three
files: `~/.mcp.json` (Claude Code, plain servers only — hledger, neovim, nixos),
`~/.cursor/mcp.json` (plain plus secret-backed) and the SOPS-rendered
`~/.config/opencode/opencode.json` (everything, plus the opencode-only gitlab and
sonarcloud servers and the ollama, Console and bedrock providers). opencode
therefore already held a superset of Claude Code's MCP clients. No change.

### Why three skills never reached opencode

opencode scans `~/.claude/skills` (a symlink into this repository) and drops any
skill whose frontmatter lacks `name:`. `jira`, `mr` and `mr_review` had only
`description`, `argument-hint` and `disable-model-invocation`, so Claude Code
saw eight skills and opencode saw five. The fix is one added line per file.
`mr_review` became `name: mr-review`: opencode wants lowercase hyphen-separated
names, and a name that differs from the folder name is tolerated — the existing
`sanity_check/` directory with `name: sanity-check` proves it loads.

### Plugin-carried skills were the second gap, and the scope was cut deliberately

Skills that ship inside Claude plugins live under `~/.claude/marketplaces/*`
(clone-or-pull by `claude.nix` activation) and no scan path ever showed them to
opencode. The user scoped the exposure to obsidian-skills only — six skills
(obsidian-markdown, obsidian-bases, json-canvas, obsidian-cli, defuddle, knap),
all with valid `name:` frontmatter and CLIs already on PATH through the same
`claude.nix` module. Ponytail, claude-reflect and replica were excluded: the
first two are hook-driven and would be half-dead in opencode, and replica was
not requested. opencode command wrappers for `$ARGUMENTS` parity were offered
and declined; the three dotfiles skills will parse arguments from chat context.

### The schema had moved, and the skill document was stale

`https://opencode.ai/config.json` defines `skills` as either a plain array of
strings or the older `{ paths, urls }` object — and marks the object form
deprecated. The planned `skills.paths` edit became a `skills = [ ... ]` array
instead. The array points at
`~/.claude/marketplaces/obsidian-skills/skills`, reusing the clone the Claude
pipeline already maintains rather than adding a second copy under
`~/.config/opencode/skills/`.

### Changes and checks

- `.claude/skills/jira/SKILL.md`, `mr/SKILL.md`, `mr_review/SKILL.md`: added
  `name:` lines. No stow needed — `~/.claude/skills` is a symlink here.
- `~/.config/nix/modules/features/home/mcp/render.nix`:
  `opencodeJsonContent` gained the `skills` array (change recorded in the nix
  repo journal too).
- Sanity check: the Makefile has no test target; verification was a
  `nix-instantiate --parse` of render.nix (OK) and a read-back of all four
  edited files. `python3 -c "import yaml"` failed (no PyYAML on the host), so
  frontmatter was verified by eye against the schema rules.
- Both changes need a `home-manager switch` and an opencode restart to take
  effect; neither was run in this session.

### Cross-repo relationship

The three SKILL.md edits live in this repository; the skills-array edit lives
in `~/.config/nix`. opencode bridges them at startup: it reads the rendered
`opencode.json` for the extra path, then loads both that path and the
`~/.claude/skills` symlink back into this repo. Claude Code sees no behavioural
change from the `name:` lines — `name` is standard skill frontmatter there.

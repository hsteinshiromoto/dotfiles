# 2026-11-17

## The dashboard quote moved to the bottom and is centred on the whole dashboard

The `fortune -s` section sat second in `.config/nvim/lua/plugins/snacks.lua`, directly under the header and above the keys. It now renders last, below every other section, and each of its lines is centred on the full width of the dashboard rather than on one pane column.

Centring it needed more than `align = "center"`. Snacks lays sections out in pane columns and aligns each section inside its own column, so a centred section lands on the centre of pane 1, about half a pane left of the screen centre. Snacks does re-centre a pane 1 line that is wider than one pane, and indenting the quote by a whole pane buys that re-centring, but the shift is clamped at `(" "):rep(negative)`. Below about 185 columns the clamp bites and the line falls back to a left edge at column 64. That approach was measured and discarded.

What works is to claim the rows as blank text and write them by hand in a `render` callback. `D:render` calls `item.render(self, pos)` after it builds `self.lines` and before `D:render_buf` writes those lines to the buffer, so the callback can replace `dash.lines[row]` with its own string. At that point the dashboard knows `dash.col`, its left edge, and `#dash.panes`, the number of pane columns that fit, so the correct left pad is `dash.col + (width - strwidth(line)) / 2`. The result is exact at every width tested: 200, 150, 124 and 100 columns, the last of which falls back to a single pane.

Highlighting has to wait. `D:render_buf` collects its extmarks during the same pass that builds the lines, and a `render` callback cannot add to that list. The callback schedules its own pass instead, on a private namespace, which runs after the lines reach the buffer. It clears the namespace first, because `D:update` runs again on every resize.

The quote is also no longer a `terminal` section. A terminal section draws a floating window over a terminal buffer, and `ttl = 0` meant the output was never served from the cache, so every start showed the live terminal with its cursor block and the `[Process exited 0]` line that Neovim appends when the job ends. The other terminal sections, Tasks and Weather, have a non-zero `ttl` and are served from a cache buffer, which is why only the quote showed the artefacts. The quote now runs `fortune -s | fold -s -w 60` through `vim.fn.systemlist` once per session. The result is cached in a file-local variable, because `D:update` runs on every resize and a new quote on resize is jarring.

`quote_gap = 3` sets the blank lines above the quote. Top padding on the item itself does not work: `D:format` inserts the top padding rows at the front of the block and `D:render` sets `item._` on the first of them, so a terminal float would start on the padding row and a `render` callback has to skip over it. The three rows are measured in the buffer, between the startup line and the first quote line.

Two limits are known. An attribution line such as `-- Spock, "The Enterprise Incident",` carries the indent that `fortune` itself writes, so it sits a few columns right of centre; only trailing whitespace is stripped. The callback also writes its rows unconditionally, so pane 2 content on those rows would be overwritten if pane 2 ever grew taller than pane 1.

The layout was measured with Neovim in `--headless` mode. A headless session does not open the dashboard by itself and reports 80 columns, so the script sets `vim.o.columns`, calls `require("snacks").dashboard.open()` and then reads the buffer lines, the extmarks and the floating window positions.

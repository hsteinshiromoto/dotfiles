# 2026-10-10

## Wide markdown tables fit the window

### The request

A wide markdown table did not render correctly. A table row is one buffer
line, so Neovim wrapped it at the window edge and the column separators lost
their alignment. The request asked for a new plugin that wraps such a line
naturally.

### No new plugin was needed

`render-markdown.nvim` 8.14.0 added `pipe_table.wrap` on 2026-09-14. The option
fits a wide table to the window and wraps each cell over several virtual lines.
This repo pinned 8.13.0 from 2026-06-18, one release behind, so the option did
not exist here. The pin now points at `245956d`.

Every precondition was already in place: Neovim 0.12.5, a rendered
`conceallevel` of 3, and the `padded` cell mode. The option needs all three and
disables itself without a message when one is missing.

Only the `render-markdown.nvim` line of `lazy-lock.json` moved. The lockfile had
drifted from the installed state for 24 other plugins, and `:Lazy update`
rewrote every one of them. Those lines went back to their old values, because a
bump of 24 plugins is a separate decision. The drift is still there and still
needs an answer.

### Two faults found on the way

The spec set both `opts` and a `config` function that took no arguments.
lazy.nvim runs `setup(opts)` only when no `config` exists, and this function
called `setup()` with a table of its own. So `file_types` never reached the
plugin and Avante buffers got no rendering at all. Both now live in a single
`opts` table, and a probe confirms that the plugin receives
`{ "markdown", "Avante" }`.

The fitted table still lost its right border. The heading signs `H1` to `H6`
widen the gutter, but `signcolumn = "auto"` widens it only after the plugin
measures the window (`lib/env.lua:262`). The plugin therefore drew 83 columns
into a text area of 81, the virtual lines were cut on the right, and the final
`│` of each header row wrapped onto a screen line of its own.
`win_options.signcolumn.rendered = "yes"` pins the gutter first, because the
plugin applies window options before it parses (`core/ui.lua:104`). The schema
for `win_options` takes any window option name, and the config merge is a deep
one, so the `conceallevel` entry of the plugin survives.

### A limitation worth recording

The cursor on a wrapped row brings back the raw source line, and that line
wraps at the window edge as before. A virtual line cannot hold the cursor, so
the plugin has to either skip the row or show the text under it. The author
closed this as not planned (issue 692) and offers only `wrap = false`. Any
hand-written plugin meets the same wall, which is the reason none was written.

### Verification

A fixture outside the repo held four tables: wide prose cells, inline links,
alignment markers, and a table on the last line with no blank line after it.

1. The plugin placed 7 `conceal_lines` marks and 4 `virt_lines` blocks, which is
   the new path that replaces a row rather than overlaying it.
2. Every virtual line measured exactly the width of the text area.
3. A capture of the rendered screen showed closed borders on all four tables,
   wrapped cells with aligned columns, and the alignment indicators in place.
4. The cursor on a row revealed the source and leaving it restored the render.
5. A note under a `.obsidian` directory still loads no renderer, so the vault
   path is unchanged.
6. `make espanso-test` passes.

# 2026-10-02

## Request

Switch the gpg-agent pinentry at runtime, from the shell, in the shape of the
existing `ykr` alias. Either send the PIN prompt to the terminal, or send it to
the GUI.

## Why the obvious answers were wrong

The nix repository already documents this problem at
`modules/features/nixos/yubikey.nix:11-85`. thinkpadt14 pins `pinentry-qt`, and
that fails on a VT and over SSH. The header offers one recipe: stop the systemd
agent and run a second one with `--pinentry-program pinentry-curses`.

Two cheaper ideas were measured and rejected before the recipe was ruled out
as too heavy.

| Idea | Outcome |
|---|---|
| A wrapper that picks the flavour itself | Cannot work. `$DISPLAY`, `$GPG_TTY` and `$TERM` travel caller to agent to pinentry over ASSUAN, after the exec, so they are not in pinentry's environment. The nix header already records this and names dev.gnupg.org T5551. |
| `gpg-connect-agent updatestartuptty /bye` | Works, but it is the wrong tool. It moves where the prompt draws. It does not choose the binary, which is fixed when the agent starts. |
| A helper script in the nix yubikey aspect | Cannot work, and this was offered to the user in error. The second-agent recipe has to export `GPG_TTY` and `SSH_AUTH_SOCK` into the CALLING shell. A script's exports die with its subshell, so only a shell function can do it. |

## What the GnuPG source says, and it beats all three

Two facts, both read out of `agent/gpg-agent.c` rather than assumed:

1. `pinentry-program` is handled inside `parse_rereadable_options`. A reload
   therefore picks up a change. The agent keeps its cached PIN and its ssh
   sockets.
2. gpg-agent parses the system config and then the user config, through
   `gpgrt_argparser` with `ARGPARSE_FLAG_SYS` and `ARGPARSE_FLAG_USER`. The user
   file is parsed last, so a single-valued option set there wins.

The nix module writes `/etc/gnupg/gpg-agent.conf` through
`programs.gnupg.agent.settings`, and that path is a read-only store symlink.
`~/.gnupg/gpg-agent.conf` is unmanaged — no `programs.gpg` and no
`programs.gnupg` anywhere in the nix repository — so it is the writable lever.

One line in the user file plus `gpgconf --reload gpg-agent` replaces the whole
six-step recipe. No agent restart, no socket juggling, no lost PIN.

## What went into `.zshrc`

One function and four names, after the `ykr` alias:

| Name | Action |
|---|---|
| `ykt` | Prompt on the terminal (`pinentry-curses`) |
| `ykg` | Prompt on the GUI (`pinentry-qt`) |
| `ykd` | Drop the override, back to what nix declares |
| `ykp` | Report which pinentry is in force |

`_pinentry_set` does the one job. The three aliases name it. `ykp` mirrors the
real precedence: the user override if one exists, otherwise the nix line.

`command -v` resolves the absolute path at write time, so the snippet needs no
`/run/current-system` assumption and works on the Macs. On mbp2023 that means
`ykt` works through the Homebrew `pinentry-curses` and `ykg` fails loudly,
because no `pinentry-qt` is installed there. That is the designed outcome.

## Tested

`zsh -n .zshrc` passes. The function was then exercised in a sandbox, with a
throwaway `GNUPGHOME` and fake `pinentry-*` and `gpgconf` binaries on PATH:

| Case | Result |
|---|---|
| Set curses | Line written |
| Set qt after curses | Line REPLACED, file still one line, no duplicate |
| `ykp` | Reports the active line |
| No argument | Line removed, file empty |
| Bogus flavour | Loud message on stderr, exit 1, file untouched |
| An unrelated setting present | `default-cache-ttl` preserved |

## The hazard, and it is the reason `ykd` exists

This override outlives the shell and the reboot. The second-agent recipe dies
with the shell, and this does not. **curses left in force gives the sops-nix
user service no terminal to prompt on.** That failure arrives as
`sops-install-secrets: ... 0 successful groups required, got 0`, which reads
like a missing key or a corrupt file and is neither. The nix header records the
same trap at lines 20-27.

Run `ykd` before a switch or a logout. `ykp` tells you where you stand.

`ykg` on a VT still does not draw, because qt has no display there. The flavour
is a choice. A prompt with no destination is not fixable by choosing one.

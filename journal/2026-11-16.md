## `make stow` linked into `~/Projects`, not `$HOME`

`stow` with no `--target` writes to the parent of the package directory. This repository lives at `~/Projects/dotfiles.linux`, so the parent is `~/Projects`, not `$HOME`. Every `make stow` run built its symlink tree one level too high. `~/Projects` still holds the result: `~/Projects/.zshrc`, `~/Projects/atuin`, `~/Projects/btop` and about thirty more links that no program reads.

The fix adds `--target="$$HOME"` to the three `stow` calls in the `Makefile`, at lines 21, 27 and 31. `README.md` needed no change, because it already said these commands stow into `$HOME`. The documented behaviour was right and the code was wrong.

The `find ... -delete` at `Makefile:25-26` was more dangerous than it looked. It deletes every symlink under `$HOME`, to depth 4, whose target starts with the repository path, and it then rebuilt them in the wrong place. With the target fixed, the deletion does the job `README.md:115` describes: it clears the hand-made absolute links that `stow` refuses to adopt.

`make stow-check` now plans the tree under `$HOME` and reports 29 conflicts. All 29 are hand-made absolute links, such as `.zshrc`, `.tmux.conf` and `.config/nvim`. The `find` step in the `stow` target removes those before `stow` runs, so `make stow` resolves them. `make stow` was not run.

Two items are left open. The links already written into `~/Projects` are relative, so the `find` pattern `-lname "$(CURDIR)/*"` does not match them and they stay as garbage. `make stow-check` also plans to link `tmux-client-38373.log` and `.mypy_cache` into `$HOME`, which `.stow-local-ignore` should exclude.

## Kitty uses the Tokyo Night night theme

The theme itself was already in the repository. `ab9ad15` added `.config/kitty/tokyonight_night.conf` and the `include ./tokyonight_night.conf` line at `.config/kitty/kitty.conf:968`. What was missing was the link: `~/.config/kitty` did not exist, so Kitty read none of it and showed its built-in colours.

`stow --dir=.config --target="$HOME/.config/kitty" kitty` creates the two file links. The package directory is `kitty`, so its contents go to the target, which must therefore be `~/.config/kitty` and not `~/.config`. With `--target="$HOME/.config"` the two files land loose in `~/.config`.

An existing symlink at `~/.config/kitty` must be removed first. `stow` follows it into the repository and plans to write the links inside the repository itself, which would overwrite `kitty.conf` with a link to itself.

# 2026-11-25

## tmux popups got their colours pinned, because tmux 3.8 started supplying its own

A `display-popup` on mbp2025 came up a pale grey that matched nothing else on screen, while the same popup on the other hosts still took the pane background. The config was identical on all of them, so the difference was tmux itself. mbp2025 runs tmux 3.8, from `/run/current-system/sw/bin/tmux`, and `tmux show -g popup-style` there reported `bg=themedarkgrey,fg=themewhite` with `popup-border-style bg=themedarkgrey,fg=themelightgrey`. Neither string appears anywhere in `.tmux.conf` or in `~/.config/nix`. They are tmux's own defaults.

Recent tmux carries a built-in theme: the `dark-theme-*` and `light-theme-*` options define the named colours `themeblack`, `themewhite`, `themedarkgrey` and the rest, picked by whether the client reports a dark or a light background, and the shipped default for `popup-style` is written in those names. `popup-style` has existed since 3.2, but it used to default to nothing, so a popup inherited whatever the pane had. The other hosts run an older tmux and still behave that way. Their exact versions were not checked.

`.tmux.conf` now sets `popup-style "fg=colour255,bg=#16161e"` and `popup-border-style "fg=#7aa2f7,bg=#16161e"`, which are the Tokyonight values already used by `window-active-style` and `pane-active-border-style`, plus `popup-border-lines rounded`. Pinning all three means the popup looks the same on every host no matter which tmux is installed, and a future tmux changing its default theme cannot move it again. The three lines sit after `pane-border-format` so the pane group stays intact.

`popup-border-lines` needs tmux 3.2 or newer. Any host below that will throw an error when it sources the file.

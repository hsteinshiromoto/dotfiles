# 2026-11-28

## A humanize skill, and the watermark that does not exist

The ask was a `/humanize` skill that detects and removes the signs of AI writing, and that removes the watermarks Anthropic and OpenAI put in their output.

Half of that ask has no referent. Neither vendor ships a text watermark. The characters people point at are ordinary typographic ones: U+202F narrow no-break space, U+00A0 no-break space, U+200B zero-width space. All three predate the models by decades and carry no payload. OpenAI called the U+202F artefact "a quirk of large-scale reinforcement learning, not a watermark", and it stopped appearing within days of the April 2025 o3 release. Google's SynthID marks images, not text. So the skill does character normalisation and says so in its own text rather than claiming a capability it does not have.

The skill also makes no promise about a detector score, because none is available to make. Fourteen detectors evaluated together all scored below 80% accuracy, and they flag non-native English writers about twelve times more often than native speakers.

## The split

Two files, because the work splits cleanly in two.

`unslop.py` does the deterministic half: Unicode normalisation, per-vendor paste residue (`contentReference[oaicite:1]`, `[cite: 1]`, `grok_card`, DeepSeek lenticular brackets, `ppl-ai-file-upload`), unfilled placeholder brackets, and the `utm_source=chatgpt.com` and `referrer=grok.com` parameters that chatbots add to the URLs they cite.

`SKILL.md` holds the half that needs judgement: the rhetoric, syntax, diction and formatting tells, as four ordered passes. Significance inflation and the trailing participle tag come first because they carry the most text. Putting the copula back — `serves as` to `is`, `boasts` to `has` — comes next.

The skill ends by calling `ste_writing` rather than repeating it. `/humanize` removes the tells; `ste_writing` makes what is left plain.

`disable-model-invocation: true`, same as `grill-me`. Without it the skill would race `ste_writing`, which CLAUDE.md already mandates for all prose.

## Two refusals built into the script

It reports em dashes and en dashes and never rewrites them. Both are legitimate punctuation, and a blind substitution damages correct prose. The word list that calls the em dash an AI tell is also out of date: Wikipedia now dates em-dash overuse as a historical indicator ending September 2026, and a July 2026 study found only Claude using them more than professional writers, with ChatGPT using them less.

It refuses to strip U+200C and U+200D from any line that is not plainly Latin script. Those are required letters in Devanagari, Arabic and Persian, and they join emoji sequences. `--aggressive` overrides the guard and will corrupt such text.

The script also reports by default and edits only under `--write`, and it exits 1 in report mode when it finds anything, so it works in a pre-commit hook.

## Where it landed, and why not in the nix repo

It was built first in `~/.config/nix` as `modules/features/home/claude_humanize.md` plus a `home.file` link, matching `grill-me`. That was wrong, and the reason is worth recording.

`~/.claude/skills` is a stow symlink into this repository. A `home.file.".claude/skills/humanize/SKILL.md"` entry therefore resolves to a real tracked file here. mbp2023, mba2022 and thinkpadt14 set `home-manager.backupFileExtension`, so there home-manager would back the file up and shadow it with a store link. mbp2025 sets none, so the switch would fail outright on the collision.

So the two are mutually exclusive, not redundant. The nix change was reverted and the skill lives here, at `.claude/skills/humanize/`, beside the other hand-written ones. It needs no rebuild and no `stow` re-run: the symlink makes it live as soon as the files exist.

## What was verified

The character tables were read back by codepoint, because they were typed as literals and a duplicate key would have been silently dropped: 25 distinct entries in `TRANSLATE`, 4 in `INVISIBLE`, 2 joiners, 2 report-only.

A crafted file then exercised each class at once. Fenced code and inline code came through untouched. `क्‍ष` and the three-person emoji family kept their joiners. `INSERT_SOURCE_URL_30` was missed on the first run — `[A-Z_]+` stops before the digits — and the fix was `[A-Z0-9_]+`. Stripping the UTM parameter left `?&x=1`, now collapsed to `?x=1`. Removing residue left a double space, now closed, though not at the end of a line where two spaces mean a line break in Markdown. A second run changed nothing further, so the script is idempotent.

Last, the same test ran through `~/.claude/skills/humanize/unslop.py` rather than the repository path, to confirm the stow symlink resolves.

## What was left out

No README change. The tree in README.md lists `.claude/skills` and does not enumerate the skills inside it, and `ste_writing` and `graphify` went in without one.

No test file. The checks above were run by hand and not committed.

The word lists in `SKILL.md` are dated on purpose. `delve` in arXiv abstracts went 0.04% in 2022 to 0.35% in 2024 and back to 0.02% in 2026, below where it started; the 2026 replacements are `underexplored`, `grounded`, `aligns`, `synthesizes`, `reproducible`. The skill says the list moves and should be read as a sample, not a rule.

# 2026-11-24

## superfile copy, cut and paste moved onto the vim keys

`.config/superfile/hotkeys.toml` now binds `copy_items` to `y`, `cut_items` to `d` and `paste_items` to `p`, so `d` then `p` moves a file and `y` then `p` copies one. The defaults it replaces, `ctrl+c`, `ctrl+x` and `ctrl+v`, stay on as the second binding of each hotkey, and `ctrl+w` stays on paste. Nothing was dropped: superfile's own docs give `copy_items = ['ctrl+c', 'y']` as the example of how to write a two-key list.

The one collision was `p`, which `focus_on_process_bar` held. It moves to `b`, for bar, which keeps the single-letter focus family together with `s` for the sidebar and `m` for the metadata panel and was unbound before. The move was not optional. superfile does not check its hotkeys for conflicts, so a key bound to two actions silently runs one of them, and the choice is not documented.

`d` does not delete. `delete_items` is still `ctrl+d` and `delete`, which matches superfile's own design rule that anything destructive wants a modifier or a confirmation.

This is the host-local file, not a declaration. superfile is enabled through the Home Manager module at `~/.config/nix/modules/features/home/shell.nix:58`, but `programs.superfile.hotkeys` is still empty there, which is why superfile wrote this file itself and why editing it works. Setting that option later would make Home Manager generate `hotkeys.toml` from the store and overwrite these four lines. A partial declaration would be enough if it ever happens, because superfile falls back to the default key for any hotkey the file leaves out.

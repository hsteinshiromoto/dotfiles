# 2026-11-09

## Superfile: pin Notes and Projects, and track pinned.json in the repo

Pinned `~/Notes` and `~/Projects` in superfile, and moved `pinned.json` into this repository so the pins are version controlled.

Superfile splits its files across two directories. The configuration directory (`config.toml`, `hotkeys.toml`, `theme/`) was already in the repository through the `.config/superfile` symlink. The data directory holds `pinned.json` plus volatile state (`superfile.log`, `firstUseCheck`, `lastCheckVersion`, `themeFileVersion`, `toggleDotFile`, `toggleFooter`). On macOS that directory resolves to `~/Library/Application Support/superfile`.

The data directory cannot be relocated. `src/config/fixed_variable.go:40` derives it from `xdg.DataHome`, so the only override is the `XDG_DATA_HOME` environment variable, which would move every other XDG application's data as well.

The fix is a single file symlink, the same pattern already used for espanso:

```
~/Library/Application Support/superfile/pinned.json -> ~/.config/superfile/pinned.json -> ~/dotfiles/.config/superfile/pinned.json
```

The symlink survives superfile's writes. Both writers (`src/internal/ui/sidebar/sidebar.go:60` and `src/internal/ui/sidebar/directory_utils.go:143`) use `os.WriteFile`, which opens with `O_TRUNC` and follows symlinks instead of replacing them. `initJSONFile` (`src/cmd/main.go:248`) only writes when `os.Stat` fails, and `os.Stat` follows symlinks too. A write test through the link confirmed both the link and its contents survive.

Two things to remember:

- Superfile rewrites `pinned.json` when it exits. Close every running instance before editing the file by hand, or the running session overwrites the edit.
- `pinned.json` stores absolute paths with the username baked in, so it does not transfer to a Linux host as-is.

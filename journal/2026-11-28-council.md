# 2026-11-28 — the council on humanize

The `humanize` skill shipped this morning as commit 72140d6. An LLM Council reviewed it the same day: five members, four steps, then this. The review found nine defects in a 224-line script that had already been tested by hand, and the most damaging one had nothing to do with anything the design worried about.

## The link that lost its label

`See [Name of the repository](https://example.com/x) here.` came back as `See (https://example.com/x) here.`

The placeholder pattern that catches `[Your Name]` and `[Article Title 1]` also matches a Markdown link label, and `--write` deleted it. No member raised this in their independent take; it surfaced only when a member went looking for false positives in the residue patterns. A `(?!\()` lookahead closes it.

Three more of the same class. `attached_file` is a real API field name and the script deleted the word from prose. `INSERT_OR_REPLACE` is SQL, and `\bINSERT_[A-Z0-9_]+\b` swallowed it. YAML front matter was read as prose, so `title: "He said “hi”"` came back as invalid YAML. All of them are a pattern applied in place with no false-positive guard, which is the same fault as the primes below.

## The primes

`37°48′27″S` became `37°48'27"S`. A prime is a measurement glyph — feet, inches, arcminutes — and never a quotation mark, so the mapping was wrong in every case it fired. Inside a quoted CSV field it turned one row into two.

This was the only motion the council carried five to nil. The copy editor found it; the engineer conceded it and reproduced the CSV collapse.

## The script destroyed its own source

`--write` on a `.py` file holding a curly quote inside a string literal ends the string. Run on a copy of `unslop.py` itself, it produced a `SyntaxError` at line 100.

The fix is a suffix allowlist gating `--write` — `.md`, `.markdown`, `.txt`, `.rst`, `.org`, `.adoc`, and no suffix at all. An allowlist, not a blocklist, so an unknown suffix fails closed. The council split on where the guard belonged and settled it plainly: a list written into `SKILL.md` binds nothing, because the script is run from a shell and from hooks where no model ever reads the prompt. The guard is in the script or it does not exist.

## Two silent false-cleans

An unclosed code fence left `in_fence` true to the end of the file, so every artefact after it was classified as code and the run reported the rest of the file clean. A non-UTF-8 byte raised an uncaught `UnicodeDecodeError` that abandoned the whole batch, after earlier files had already been written.

A tool that reports clean on a dirty file is worse than one that crashes loudly. Both now report: the fence warning names its opening line, and an unreadable file is skipped with the batch continuing and the exit code set to 2.

## The exit codes meant nothing

`SKILL.md` advertised a pre-commit hook. The script exited 1 on a file whose only finding was an em dash — a character it refuses to rewrite — so no edit could make the gate pass except deleting correct punctuation. Stdin returned 0 unconditionally. `--write` returned 0 after modifying files, so a hook would rewrite the tree and commit the old staged content.

Now: 0 nothing to do, 1 findings in report mode or files changed under `--write`, 2 a file could not be read. Report-only findings never raise it.

## Two prose changes, and what settled them

**Restore became keep.** Pass 3 told the editor to restore superlatives and intensifiers because models under-use them. Writing *was the first* into a sentence asserts a fact the source may not support, and the same page forbids changing what the text claims. Three members reached this independently by three different routes. The bullets survive with the verb changed: keep what the author wrote, never insert.

**The `ste_writing` handoff is gone.** It capped sentences at 20 words and banned semicolons, which reverses Pass 3's sentence variance and Pass 4's punctuation variety — the two edits doing most of the work. STE-flavoured mode is not an escape: it relaxes the dictionary and keeps the sentence discipline. The two skills are alternatives, chosen at the start, not a pipeline.

In its place the Finish section now says to re-run `unslop.py --write` at the end. Passes 2 to 4 generate prose, and generated prose arrives with fresh curly quotes; the first run cannot normalise text that did not exist yet. Nobody noticed that hole until the fourth step.

## What was rejected

**Four-space indented code blocks stay unprotected.** Treating an indented line as code would silently skip every continuation paragraph under a bullet, which is common in these repositories. Four of five rejected it: a routine silent skip is worse than a rare reported rewrite. A `shortcut:` comment names the limit.

**The `--to-ascii` flag.** Its own proposer withdrew it after measuring: on an ordinary prose file, curly quotes and the ellipsis were nearly every hit, so putting them behind an opt-in would make the default run a no-op.

**A prose linter** that would copy 71 tell patterns out of the prompt into Python. Measured over 205,020 words of journal entries, the prototype fired twice.

**A `PostToolUse` hook** wiring Pass 1 into every `Write` and `Edit`. That reinstates automatic invocation through the back door, against the `disable-model-invocation` flag the skill sets on purpose.

**The voice-anchored pass**, and this is the finding worth keeping. The proposal was to measure the author's own voice from `~/Projects/nix/journal/*.md` and move the draft toward it. The objection was that those entries were written by Claude. It checks out: 242 of the 304 commits touching that directory carry a `Co-Authored-By: Claude` trailer, and 24 of 31 in this repository. The `/journal` skill produces them. A voice pass anchored to that corpus would measure the model and train the skill to preserve the tells it exists to remove. There is no clean corpus of this author's own prose on this machine, so the idea has nothing to anchor to.

## The council itself

`llm_council/SKILL.md` said each member "will use the grill-me skill". That cannot work as written: `grill-me` routes every question through `AskUserQuestion`, and a subagent cannot reach the user, so a member following it literally stalls. The first run of the council skipped it silently.

The skill now says the grilling is amongst themselves, bars `AskUserQuestion` inside members, and names four steps instead of three — takes, questions, answers, chairman. The answers round is where the work happened: it produced three public concessions, and two members voted against motions they had argued for in the previous round.

## What is not done

The tests live in `utils/test_unslop.py`, 38 checks, because `.stow-local-ignore` keeps `utils/` out of the link set — a test file under the skill directory would be stowed into `~/.claude/skills/humanize/` and offered to the agent as part of the skill. Nothing runs them automatically.

One false positive is kept on purpose: `[cite: 1]` is stripped from prose that discusses the marker. The tell value is high and the collision only happens when writing about AI tells, which is a narrow case. The limit is recorded in both files.

CRLF input is still written back as LF. No host here is affected, and the repository's own quality gate rejects any file containing a CR, so the conversion is what the gate wants.

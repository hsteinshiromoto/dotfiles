# 2026-10-30

## `stow .` never worked: a blanket `*.yml` ignore, basename-anchored rules, and 26 conflicts

### The state before

`stow -n -v .` aborted with 26 conflicts and, where it did link, linked the wrong set. Three separate faults, one symptom.

The first was a blanket ignore. `.stow-local-ignore` held `^.*\.yml$` and `^.*\.yaml$`. Stow applies the package's top-level ignore list at every depth, so those two lines hid 18 tracked configuration files: all of `.config/espanso/{config,match}`, `.config/lazygit/config.yml`, `.config/eza/theme.yml`, the seven `.config/tmuxinator/*.yml` and `.config/code-server/config.yaml`. They reached `$HOME` only by accident, when stow folded a whole directory into a single symlink and the per-file ignores stopped applying. The rules were there to stop `docker-compose.yml` from landing in `$HOME`; one path-anchored rule does that job.

The second was anchoring. Every repository-only rule used the basename form (`^Makefile$`), which matches at any depth, while several entries were simply missing. The dry run showed stow creating `~/Justfile`, `~/LICENSE`, `~/journal`, `~/pam_biometric.so` and `~/.gitignore_global`.

The third was drift. `^keyboards$`, `^roles$`, `^usr$`, `^nvim\.Dockerfile$` and `^nuphy_air75_v2\.layout\.json$` pointed at paths that no longer exist. `.stowrc` carried a second, overlapping ignore list whose `--ignore=DS_Store` never matched anything, because stow anchors the pattern and the file is named `.DS_Store`.

### Two pattern forms, and why the distinction matters

Stow matches a pattern without `/` against the file name at any depth, and a pattern with `/` against the path from the repository root, which starts with `/`. The rewritten `.stow-local-ignore` uses the path form for everything that is repository infrastructure and the name form only for junk such as `^.*\.DS_Store$`. The `^...$` anchors and the leading `^.*` on suffix rules stay: stow anchors patterns internally, so a bare `\.swp$` would match a file literally named `.swp` and nothing else.

### What stays out of `$HOME`, and why

`.ssh/config` and `.gnupg/gpg-agent.conf` are now ignored outright. Both home files had diverged and carry machine-specific lines — a `/nix/store` pinentry path, extra `Host` entries — so linking either one would have replaced working local state with a stale copy. `.gitconfig` and `.gitignore_global` stay ignored too; the real `~/.gitconfig` is a two-line GitLab `insteadOf` override and the repository file is a full configuration, so a link in either direction loses something.

`.lima` joined the list because lima writes instance state into that directory, and a folded symlink would route that runtime junk into the repository. `.claude/settings.local.json` is machine-local and already differed from the home copy.

One ignore was found during verification rather than planned: `.config/opencode/opencode.json`. The repository tracks it, but `~/.config/opencode/opencode.json` is a link to `~/.config/sops-nix/secrets/rendered/opencode.json`. Stowing it would have replaced the SOPS-rendered file with the template. The tracked copy holds placeholders and `{env:...}` references only, no plaintext secret.

### The conflicts stow could not resolve by itself

Thirteen paths in `$HOME` were hand-made **absolute** symlinks into this repository — `~/.config/{espanso,atuin,claude,ghostty,lazygit,television,yazi,opencode/agents}`, `~/.claude/{agents,commands,skills,CLAUDE.md}` and a dangling `~/commands`. Stow refuses to take over a link it did not create and stops with `existing target is not owned by stow`. The `make stow` target now deletes any `$HOME` symlink whose target string starts with this repository's path, then runs `stow --restow`. Stow's own links are relative (`../dotfiles/...`), so they never match the `find` and are handled by `--restow` as usual. `~/commands` pointed at a path that no longer exists and was not recreated.

`~/.config/superfile` was the other class: real files, not links, so stow could not place anything. The user chose the repository version. The home directory moved to `~/.config/superfile.bak`, which keeps the home-only edits (`theme = 'catppuccin'` and a modified `tokyonight.toml`) recoverable until superfile is confirmed working.

### Changes

- `.stowrc`: ignore rules removed, options only (`--verbose=1`).
- `.stow-local-ignore`: rewritten and grouped by reason.
- `Makefile`: `stow-check` (dry run), `stow` (clean stale links, then `--restow`), `unstow` (`--delete`); all three added to `.PHONY`.
- `README.md`: the workflow section now documents the three targets and the two pattern forms instead of raw `stow .` and `stow . --adopt`.

### Checks

`make stow-check` exits 0 with no conflicts. `make stow` created the 13 replacement links and linked superfile. `~/.ssh/config`, `~/.gnupg/gpg-agent.conf`, `~/.gitconfig` and `~/.claude/settings.local.json` are still real files; `~/.config/opencode/opencode.json` still points at the SOPS-rendered file. `make espanso-test` passes. The unstow path was checked with `stow --delete --no --verbose .` rather than a live round trip, to avoid a window with no configuration linked.
